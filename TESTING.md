## Execution status

This is a partially executed plan. Live HTTPS checks were run against GitHub Pages, not Live Preview. The evidence file records the deployed HTML link checks and asset responses. These checks verify URLs, HTTP status, titles, active navigation markers, and fragment targets; they do not verify browser clicks, rendering, JavaScript execution, keyboard behavior, or accessibility scores.

No browser is connected in this session (browser inventory is empty). A remote Lighthouse accessibility request through the PageSpeed Insights API returned HTTP 429. No Lighthouse score was obtained. Browser-dependent cases are explicitly marked **Blocked (not run)** rather than given an invented Pass or Fail. Replace those entries with Pass or Fail and observed evidence after execution. A blocked test is not evidence of a site defect.

The deployed `site.js` does not contain the latest local arrow-key shortcuts, and the deployed main elements do not yet include the latest local focus-target changes. The local keyboard work remains uncommitted/unpublished. Live checks below describe the current deployment only; previous local simulations are not counted as live results.

## Setup and acceptance criteria

- Open the live URL in a current Chrome browser. Record browser version, operating system, and deployed commit before completing browser tests.
- Phone viewport: 390 x 844 CSS pixels. Laptop viewport: 1440 x 900 CSS pixels. These are browser viewport dimensions, not physical screen dimensions.
- Start with fresh site storage for default-theme checks; preserve storage when checking saved preferences. Hard-refresh after deployments to avoid stale assets.
- Test dark and light themes when checking layout and focus contrast. Both layouts must have readable content, no unintended horizontal scrolling, no overlapping controls, and visible focus.
- Use Tab and Shift+Tab to move focus, Enter to follow links, and Enter/Space to activate buttons. Do not use a mouse during keyboard cases.
- For Lighthouse, open DevTools > Lighthouse, select Accessibility and Navigation mode, and run on the exact live page URL. Run both Mobile and Desktop; record each numeric score and save both reports. The plan's acceptance target is at least 90/100 per page and profile. Manual keyboard tests remain required even if the score passes.
- The contact page has an email reveal button, not a contact form. Valid/invalid form validation cases are not applicable; no form has been added just for testing.
